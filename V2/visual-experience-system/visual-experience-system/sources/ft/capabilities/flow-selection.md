## I — 方法骨架

先确认数据表达状态变化、顺序增减或实体连接。
追踪复杂过程最终去向可考虑桑基图。
顺序正负增减可考虑瀑布图。
双向矩阵流量可考虑弦图，关系强度与互联可考虑网络。
地点间的明确移动可考虑流向地图。
输入关系结构决定候选，图形名称不替代数据核对。
输出图形与数据结构条件，流量处理和布局另需明确。

## A2 — 触发场景

- 追踪状态转移的最终去向。
- 表达预算中的顺序增减。
- 表达双向流量矩阵。
- 表达实体间关系和强度。

语言信号包括流量过程 / flow process、桑基图 / Sankey、瀑布图 / waterfall、关系网络 / network。

来源去向、过程增减和关系强度进入本卡。静态整体组成进入composition-selection；地理移动组合spatial-selection，保留方向、位置和流量口径。

以上为阶段3确定的任务边界，实际触发与输出在阶段4检验。

## E — 执行契约与步骤

### 输入契约

- 来源与去向标识，或明确的顺序增减组件。
- 流量、关系强度或组件值及单位、方向和时间范围。
- 状态链、双向矩阵或网络边表等结构说明。
- 请求地理移动时需要位置字段；流量守恒及循环处理须有约定。

数据类型、单位、范围和语义须显式核对。纯选型可接受字段说明，涉及具体数值排列的输出须有可核查数值。实现前置条件缺失时，只交付带条件的候选，并列出待补字段。

### 选型规则

|规则|条件及动作|出处|实现前置条件或限制|
|---|---|---|---|
|p62|流量跨状态变化且需追踪复杂过程最终去向时，可考虑桑基图。|README.md L408 / Flow / Sankey (aka river plot)|未给出流量守恒、损耗和循环处理规则。|
|p63|流动过程需展示有序增减时，可用瀑布图，预算是原文举例领域。|README.md L414 / Flow / Waterfall|未给出起止合计的核算公式。|
|p64|双向流量及净受益者的矩阵表达可考虑弦图，并保留其复杂性条件。|README.md L418 / Flow / Chord|未给出净额计算和方向编码规范。|
|p65|关系类型、强度和互联性是表达目标时，可考虑网络图。|README.md L422 / Flow / Network|未给出边权、布局或社区发现算法。|

### 操作步骤

1. 明确表达目标并核对输入契约。完成标准为必要的字段类型、单位和关系已知。若缺关键目标或字段，输出具体问题并停止确定性选型。
2. 区分状态链、增减过程、双向矩阵和关系网络。完成标准为关系类型和必要字段明确。
3. 按规则表列候选并说明实现缺口。完成标准为方向、量、单位和地理需求均被记录。
4. 把每个候选对应到规则与出处。完成标准为说明为何适合当前目标，以及哪些条件尚待满足。多个候选均适合时列出条件差异。
5. 按输出契约交付。完成标准为建议、适用条件、风险和缺口齐全；落入p24、p35、p38等待核查规则时停止该分支并说明原因。

### 输出契约

以表格或等价结构输出下列字段。格式为蒸馏者的交付约定。

|字段|完成标准|
|---|---|
|表达目标|明确读者要看清的关系与重点|
|候选图形|给出与当前输入匹配的候选；待补条件须显式写出|
|变量与口径|说明字段类型、单位及基准、时间、层级或地理结构等必要条件|
|选择依据|对应规则ID或类别导语及原文位置|
|使用限制|记录精度、简化、可读性与未核查分支|
|待补输入与后续动作|缺字段则提出具体问题，缺算法则指出所需实现约定|

请求只涉及选型时，给出有条件的候选即可。请求同时需要渲染、统计计算或推断时，另列实现条件，核对其来源后再执行相应工作。
