# 问题到图表类别的综合导航

## R — 原文

> Show size comparisons.

展示大小比较。该短句只示例数量类别，综合导航的依据是九类导语。

## I — 方法骨架

把读者的问题改写为需要看清的数据关系。
按偏差、关系、排名、分布、时间、组成、数量、空间或流动定位类别。
字段名称用于核对数据条件，表达目的决定先读哪张类别卡。
一个请求可能包含多个关系，先确定主要目标，再保留次要目标。
导航负责找入口，具体图形的适合性由对应类别规则核对。
没有表达重点时先询问，类别冲突时给出候选及取舍依据。

## A2 — 触发场景

- 面对一份表格，需要确定表达关系。
- 备选图形很多，需要从任务目标缩小范围。
- 一个问题同时涉及排名、空间或时间，需要明确表达重点。

语言信号包括选什么图 / choose a chart、图表类型 / chart type、如何表达这些数据 / visualize this data。

请求尚未确定表达关系时，从九类中定位主要目标，再只读取命中类别卡。目标已明确时直接使用相应类别卡。single模式由统一入口完成这些分派；pack模式将明确的七类晋级意图交给对应入口，偏差与流动及综合请求由来源路由承接。

以上为阶段3确定的任务边界，实际触发与输出在阶段4检验。

## E — 执行契约与步骤

### 输入契约

- 读者问题，字符串，包含希望看清的关系或结论。
- 字段清单，逐字段给出名称、连续值或类别或时间或地理等类型。
- 已有数据或字段语义，以及必要的单位、总体范围和采样时间。

数据类型、单位、范围和语义须显式核对。纯选型可接受字段说明，涉及具体数值排列的输出须有可核查数值。实现前置条件缺失时，只交付带条件的候选，并列出待补字段。

### 操作步骤

1. 明确表达目标并核对输入契约。完成标准为必要的字段类型、单位和关系已知。若缺关键目标或字段，输出具体问题并停止确定性选型。
2. 写出主要关系及判断依据。完成标准为九类之一或明确的复合目标。
3. 按前述路由表读取对应能力卡，再核对该类必要字段。完成标准为图形选择有类别规则支持。
4. 把每个候选对应到规则与出处。完成标准为说明为何适合当前目标，以及哪些条件尚待满足。多个候选均适合时列出条件差异。
5. 按输出契约交付。完成标准为建议、适用条件、风险和缺口齐全；落入p24、p35、p38等待核查规则时停止该分支并说明原因。

### 输出契约

以表格或等价结构输出下列字段。格式为蒸馏者的交付约定。

|字段|完成标准|
|---|---|
|表达目标|明确读者要看清的关系与重点|
|候选图形|给出与当前输入匹配的候选；待补条件须显式写出|
|变量与口径|说明字段类型、单位及基准、时间、层级或地理结构等必要条件|
|选择依据|对应规则ID或类别导语及原文位置|
|使用限制|记录精度、简化、可读性与未核查分支|
|待补输入与后续动作|缺字段则提出具体问题，缺算法则指出所需实现约定|

请求只涉及选型时，给出有条件的候选即可。请求同时需要渲染、统计计算或推断时，另列实现条件，核对其来源后再执行相应工作。

## B — 适用边界

- 仅凭日期列或地名列不能确定主要表达关系，需回到用户目标。
- 九类间没有原文给出的固定评分或优先级，复合目标应说明取舍。
- 原材料面向新闻图表沟通。来源核查支持本卡限定的选型用途，方法对实际读者的效果仍需后续输出测试。
- PDF海报、外链正文及Todo综合方法尚未纳入本轮来源验证。
